# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

MetalMD is a native Markdown viewer in Rust (egui/eframe), read-only except for ticking task list items and highlighting text (`==…==`). It is a rewrite of the viewing half of Markpad (Tauri + SvelteKit). The overriding goal is **time from process start to the first frame showing the document**. Treat any change that adds work before the first frame as a regression unless it is measured.

The name is written `MetalMD` wherever people read it (UI, window title, READMEs, installer, ProgID `MetalMD.md`, `%APPDATA%\MetalMD`, `%LOCALAPPDATA%\Programs\MetalMD`, `MetalMD_<ver>_Setup.exe`) and `metalmd` wherever it is an identifier (Cargo package, `metalmd.exe`, `metalmd.json`, the single-instance socket, the GitHub repo `Fan4Metal/metalmd`). This follows disk_flashlight (`Disk Flashlight` / `disk_flashlight.exe`).

## Commands

```
cargo build --release          # target\release\metalmd.exe (fat LTO, ~1.5 min)
cargo build                    # debug; dependencies are built at opt-level 2
cargo test                     # all unit tests (no integration tests)
cargo test wikilink            # tests whose name contains "wikilink"
cargo test markdown::preprocess::tests::copy_reference_output_becomes_a_real_link
cargo clippy --all-targets     # kept at zero warnings
cargo fmt
uv run build.py                # release build, first closing a metalmd.exe running from target\
python tools/make_release.py   # tests + release build + dist\MetalMD_<ver>_Setup.exe and _portable.zip (needs Inno Setup 6); --no-tests, --install
python tools/notices.py        # licenses\THIRD_PARTY_NOTICES.txt and SYNTAXES_AND_THEMES.txt after the dependencies change (tests fail until then)
```

Releases: pushing a tag `vX.Y.Z` runs `.github/workflows/release.yml`, which runs `make_release.py` and publishes both files. The tag must equal the version in `Cargo.toml`. `tools/setup.iss` installs per user. Its `assoc` task registers `.md`, `.markdown`, `.mdown` and `.mkd` through `[Registry]` entries: a ProgID, OpenWithProgids and Default apps capabilities. qview does this from its exe with `--register`; MetalMD has no such code. `make_release.py` gets the installer icon from `metalmd.exe --export-icon <file>`. `.cargo/config.toml` links the CRT statically, so no VCRUNTIME140.dll is needed. These scripts mirror qview's and disk_flashlight's; keep them in step.

Measure startup (writes ms-since-process-creation marks as JSON, then exits):

```
target\release\metalmd.exe --bench timings.json samples\markdown-syntax.md
```

Marks: `main`, `run_native`, `event_loop`, `window_builder`, `app_new`, `fonts_ready`, `first_frame_start`, `doc_ready`, `doc_frame_end`, `next_frame_end`. Baseline on the dev machine: `doc_frame_end` ≈ 168 ms for the 27 KB sample, ≈ 208 ms for 4.9 MB. About 130 ms of that is OpenGL context creation (`window_builder` → `app_new`). Use `--new-instance` when launching for manual testing so the single-instance hand-off doesn't route the file into an already-open window.

Release builds use `windows_subsystem = "windows"` (no console); debug builds keep the console. Any non-`--bench` run writes the settings. They go to `%APPDATA%\MetalMD\config\settings.json`, or to `metalmd.json` next to the exe when that file exists and can be written (portable mode, `settings::location`). The portable zip ships an empty `metalmd.json`.

## Architecture

### Startup pipeline (`main.rs` → `app.rs`)

1. `main` parses args, normalizes paths, and tries `single_instance::hand_off` (local socket / named pipe named after the user, the Windows session and a hash of the exe's path, so each copy of the exe has its own window, as in qview). If another instance accepts, the process exits.
2. Before creating the window, `main` spawns one loader thread per file (`app::spawn_first_load`: read → `fs_text::decode_text` → `Document::parse`). Results come back as `AppMsg::Loaded` over an mpsc channel. Note embeds, which read other files and may list a vault, are filled after the document is sent and come as a second `Loaded` of the same generation (later loads, `spawn_load`, fill them first).
3. eframe starts with the **glow** renderer. wgpu was measured slower (DX12 ~240 ms, Vulkan ~290 ms vs ~130 ms for glow). `eframe` uses `default-features = false` so wgpu is not linked; don't re-enable default features.
4. On the first frame, `App::ui` blocks briefly (`wait_for_first_document`) so the window appears with the document rather than empty. Windows shows a new window before its first OpenGL frame reaches DWM, white, so `App::new` cloaks the window (`caption::cloak`, `DWMWA_CLOAK`) while it is still hidden, and `App::uncloak` shows it once it has painted `PAINTED_TO_SHOW` (3) frames and, if it is to be, is maximized (at most `UNCLOAK_TIMEOUT`, 1 s). A window closed maximized is made at its restored place without `with_maximized` (winit shows a window made maximized at once, before its first frame) and maximized in `App::new`, cloaked (`placement::show_maximized`); `remember_window` waits for the uncloak. Fonts are set in `App::new` but only take effect at the next frame start, which is why `FontChoice::measure_ascents` runs in frame 1.
5. Deferred until frame 2 or later: file watcher, syntax-highlighter warm-up, the update check (if enabled and due; never with `--bench`), and CJK fallback fonts (loaded only if `Document::scripts` says the text needs them).

Files handed over by another launch arrive as `AppMsg::OpenPaths`, but eframe runs no frame for a minimized window, only `App::logic`. So the single-instance thread also sets `App::raise`, and `logic` restores and focuses the window they open in with Win32 (`placement::bring_to_front`); viewport commands would wait for the next frame, and winit does not focus a minimized window.

Background threads reach the UI through `CtxCell` (`Arc<OnceLock<egui::Context>>`) plus `request_repaint`. Loads carry a per-tab `generation` so stale reload results are dropped.

### Parsing (`src/markdown/`)

- `preprocess.rs` is ported from Markpad. It does text-level rewrites before comrak: Obsidian `%%comments%%` taken out first (leaving their line ends), wikilinks `[[file]]` and `[[file#Heading|alias]]` (a bare one whose label has a reference definition stays, as CommonMark reads it; a bare target without an extension gets `.md`, one with any extension links to that file), `^block-id` anchors, Obsidian embeds `![[img.png|300x200]]`, and parenthesized bare URLs. All are guarded by `code_region_ranges`, a CommonMark-accurate scanner that keeps rewrites out of code and out of the front matter (`front_matter_end`, as comrak takes it), which is YAML; wikilinks, embeds and block ids also stay out of dollar math (`code_and_math_ranges`), where `[[x]]` is TeX. Embeds of images become Markdown images whose title carries `qmd-size:WxH`; an embed of a note (no extension or a Markdown one, `#part` allowed) becomes an image titled `qmd-note`, which `document.rs` makes a `Block::Embed` when a paragraph holds nothing else (several on lines one after another are several blocks) and a link among other text; `document.rs` also reads Obsidian's size after a `|` in an ordinary image's alt text (`![alt|300x200](src)`). Block ids become `<a id=… class="block-id-anchor">`. An image whose source is a local path with an extension that is not a picture's (`is_other_file`: a PDF, a sound, a spreadsheet; web addresses excepted, `avatar.php` may be an image) becomes a link to the file, its alt text or its name. `markdown_options()` defines the dialect: GFM plus highlight, insert, inline footnotes, description lists, alerts, dollar math, front matter, and **single newline = line break**. `~sub~`, `^sup^` and `||spoiler||` are deliberately off.
- `emoji.rs` finds the emoji that a browser would draw in colour (UTS #51: `Emoji_Presentation` or U+FE0F, with skin tones, ZWJ sequences, flags, keycaps; `©` or `✔` alone stay text), using `unicode-properties`' table. `InlineCtx::push_span` makes each one a `Style::EMOJI` span of its own, outside code and math. Obsidian tags (`find_tag`: `#` at the start or after white space, then letters, digits, `_`, `-`, `/`, not digits only) become `Style::TAG` spans the same way, outside links too, each with the link `TAG_LINK` + tag, which `App::handle_action` turns into a find and print into a `<span class="tag">`. The scan skips to UTF-8 lead bytes that can begin one, so text in other scripts costs almost nothing.
- `document.rs` walks the comrak AST once into an egui-independent model (Obsidian callouts that comrak's five alert types miss, a quote starting `[!type]`, become the nearest alert in `take_callout`; a fold mark, `[!type]-` folded or `[!type]+` open, becomes `Block::Alert::fold`, numbered with the `<details>`, so the viewer toggles it through `ViewState::details` as it does them, `reveal` unfolds it for a jump, and print shows it as the reader left it; a `[!gallery]` or `[!gallery-masonry]` callout of pictures only, the reader's Media Gallery plugin, becomes `Block::Gallery`, which `draw_gallery` lays out in justified rows aiming at 300 points at the default size (`justified_rows`) or 3 columns (`masonry_columns`), a picture not loaded yet at 4:3): `Vec<Block>` with `Rich` text (string + style spans + link table). Each `Rich` and code block gets a sequential `id` in document order, and `Document::search` holds `(id, top-level block, text)` for find. Heading slugs use one `Anchorizer` per document, so ids match comrak's HTML (tests assert this against `comrak::markdown_to_html`). `Document::anchors` maps slug, block id, or `fn-<name>` to a top-level block index.
- `properties.rs` reads the front matter as Obsidian's Properties (`Block::FrontMatter::properties`): the flat YAML Obsidian writes (scalars, `- item` and `[a, b]` lists, `|`/`>` block text, quotes, comments); anything else (a nested map, anchors) is `None` and shows as YAML in a collapsed block, as before. The viewer draws a row per key (`draw_properties`), list values as chips, a value `[[Note]]` or a web address as a link; every piece goes through `selection::label` (`doc_label`).
- `embed.rs` fills each `Block::Embed` on the loader thread (`load_file`; for the first frame after it, see the startup pipeline): the note read and parsed (found next to the document or in its vault, embeds within it filled first, at most 4 deep and 64 notes, a note already in the chain refused), the whole note without its front matter, the section under a heading up to the next of its level, or the one top-level block holding a block id (`Document::anchors`). Its blocks keep the document's rules: ids moved past `Document::ids` (which counts every id given out), so selection and find tell them apart, and fold numbers past `Document::folds`, so a folded callout or `<details>` in it toggles alone; its search entries added at the embed's top-level block; links and images relative to the note made absolute, where the vault has them when they are not next to it (an anchor alone becomes the note's file); task boxes read-only (`Task::line` 0, which the viewer does not make clickable). `source::Located::new` refuses a selection with ids past the file's own (`Problem::Embedded`), and `each_part` skips embeds. The viewer draws it beside an accent bar under the note's name, a link to it; a note that cannot be shown says why. Changes to an embedded note show on F5, not by themselves.
- `html.rs` is a tiny tag tokenizer. Raw HTML is reduced to the README subset (img, a, br, aligned p/div/h*, inline style tags). `Builder::html_align` persists `<p align=center>` alignment across separate HTML blocks so Markdown between them is centered too. An HTML `<table>` becomes a `Block::Table` through `Builder::html_table` (`HtmlTable`), which stays open across blocks, since a blank line ends an HTML block: rows set apart by one are blocks of their own, and Markdown paragraphs and headings between `<td>` and `</td>` go into the cell (`add_to_html_table`). Any other block ends the table first, and so does the end of its container. A first row of `<th>` only is the header, else `Table::header` is empty (the viewer and print skip it); nested tables and `<details>` in a cell are only text, a `<caption>` is a centred paragraph above.
- `source.rs` maps a selection back to the file, for "Copy as Markdown" and highlighting. `Document::parse` keeps no positions (startup cost); `Document::parse_with_sources` builds the same document while a `Tracker` notes, per `Rich` id, each piece of text with comrak's sourcepos (`exact` when the text is the source as written, else only its ends count), the inline markup around it (`groups`, highlights also in `marks`) and, for HTML blocks, only the block. Places in the preprocessed text go back to the file through the `Rewrite`s each preprocessing pass records (`preprocess_with_rewrites`, `before_rewrites`; a place inside a rewritten wikilink becomes its start or end) and the copy markers taken out. A selection that cuts a group is grown to hold it (`take_in`), so the result is Markdown of its own; `markdown` also takes in block markup before its start (`is_block_markup`) and trailing `|`/`#`. `highlight` wraps each `Rich` on its own (one highlight cannot span paragraphs), merges highlights it cuts, and checks by reparsing that the number of highlights came out as planned. Each `Selected` carries the digest of its text, so a file changed since it was shown is refused.
- `highlight.rs` is syntect + two-face on a worker thread. `Highlighter::get` returns `None` until ready and the worker triggers a repaint. The cache key is `Block::Code::key`, computed at parse time, plus the dark/light flag.

### Rendering (`src/ui/viewer.rs`)

This file holds most of the subtle logic:

- **Virtualization.** `ViewState` keeps per-block heights, estimated by `estimate()` and then measured. Each frame lays out only the visible blocks, placed sequentially from the first visible block's offset. It also measures off-screen blocks in an invisible UI within a 4 ms budget. Heights are invalidated on width change, document identity change, or `fonts_generation` change.
- **Scroll anchoring.** The first visible block's top is remembered. If measurements above it change its offset, the scroll offset is shifted by the delta. Programmatic jumps (`jump_to(block, offset_from_view_top)`) are re-applied for several frames (`settle`) while heights converge.
- **Text.** `Rich` becomes a `LayoutJob` and is shown through `Label::layout_in_ui` plus `ui::selection::label`, which gives cross-block selection. Links are hit-tested with `char_under`. Colors use `Color32::PLACEHOLDER` so quotes and footnotes can mute text via `override_text_color`.
- **Baseline alignment.** Every run uses the paragraph's line height. Smaller or monospace runs get a reduced line height with `valign = BOTTOM`, computed from measured font ascents, so baselines line up. `first_row_min_height` stops code-only rows from shrinking.
- **Centered content.** Centered rows with images cannot use egui's expanding layouts. They pad by width remembered from the previous frame in `ui.data`.
- **`<details>`.** `html_block` turns `<details>` into `Block::Details` (its number, `open`, the `<summary>` inlines) and `</details>` into `Block::DetailsEnd`; the Markdown between them stays ordinary blocks, as comrak gives them, so anchors, find and measuring still see top-level blocks. `hidden_blocks` marks what a closed one hides (and the end markers), `ViewState::update_hidden` gives those blocks height 0 and the shown ones an estimate, and `draw_blocks` skips them in nested lists. `ViewState::details` holds the ones the reader toggled and survives reloads. A jump to a hidden block (find, contents, link) opens the details around it (`reveal`). A click on the summary row toggles it unless it was on a link.
- **Tables** do not use `egui::Grid`, which gives the last column only what is left of the view and centres cells unevenly. `draw_table` lays them out as a browser does (`table-layout: auto`): `cell_extent` measures each cell's longest word (`longest_word`, from a galley laid out unwrapped) and unwrapped width, `column_widths` gives every column its unwrapped width when they all fit, else its minimum plus a share of the rest, and a table whose minimums don't fit scrolls sideways. Each cell is a child `Ui` of its column's width, so `draw_inlines` aligns it; cells are centred vertically in their row by heights from the previous frame.
- **Pictures from text.** `ui/render_cache.rs` turns a source into a texture on a worker thread, like the highlighter: `RenderCache::get(source, variant, scale)` returns `Pending` until the texture is ready, then the picture plus scale-independent layout data (`meta`); after a zoom or resize the old texture is drawn scaled until one at the new scale arrives (`peek` reads the last one without asking). A block measured off screen while a picture in it was pending stays unmeasured (`RenderCtx::pending`). A picture set in text (formula, emoji) has `render_cache::Metrics` (width, height, depth in ems) and is painted by `Picture::paint` on the baseline, its texture starting `PAD_PX` left of and above its box. `viewer::Pictures` holds the three users:
- **Math.** `ui/math.rs` typesets TeX with RaTeX (`ratex-parser` → `ratex-layout` → `ratex-svg` with the embedded KaTeX fonts) and rasterises the SVG with resvg. The variant is display style + colour; the meta is width/height/depth in ems, the scale pixels per em. ratex-svg writes its size in `pt`, which usvg reads as 4/3 px, hence the scale in `render`. A `$$ … $$` paragraph is `Block::Math` (centred, scrolled sideways if too wide, code plus the error when it fails, "Copy TeX" in its context menu). Inline `$…$` is a `Style::MATH` span of its own (`Style::DISPLAY` for `$$` inside text); `rich_job` replaces a typeset one with a transparent no-break space whose font size makes it as wide as the formula and whose line height makes the row tall enough above the baseline, and `paint_inline_pictures` paints the formula on the row's baseline at that character (`pos_from_cursor`). `RichJob::char_bytes` maps job characters back to `Rich::text` bytes for links. egui's selection copies the job's text, so `ui/copy.rs` puts a marker of characters egui draws as nothing (U+2063, then the source's number in U+2062/U+2064 binary digits) before each picture's space, and `CopyPlugin::output_hook` replaces marker and space in `CopyText` with the source (`$tex$`, `$$tex$$`, the emoji). The marker goes before the space because the pointer puts the cursor before the marker or after the space, never inside, so a selection holds all of it or none. Until typeset (or when it fails) the TeX shows as inline code. Release builds use `panic = "abort"`, so a panic inside RaTeX or mermaid-svg ends the process.
- **Emoji.** egui draws every glyph in one colour, so a `Style::EMOJI` span is a picture too, through the same no-break space as an inline formula: `ui/emoji.rs` sets it with resvg in the system colour font (Segoe UI Emoji's COLR; Noto Color Emoji or Apple Color Emoji elsewhere), read on the worker with the first emoji. The variant is the text colour. Its width is where a trailing space lands (the shaper gives U+FE0F and joiners no advance), or its ink if wider; usvg's boxes of text are the line's and of COLR glyphs in font units, so the ink is found by drawing it with room and scanning the pixels, then drawing it again in its box. Until drawn, or when the font lacks it (newer emoji on Windows 10), it is text in egui's monochrome fallback fonts; the TOC and code stay text.
- **Diagrams.** A code block whose language is `mermaid` is drawn by `ui/diagram.rs`: mermaid-svg lays it out (text measured by character widths, no fonts) and writes SVG in Mermaid's default or dark theme (the variant), with `responsive = false` for a fixed size; resvg draws it with `svg::text_options` (system fonts). The meta is its own size in points; `draw_diagram` shows it centred at that size or scaled down to the page, and asks for the scale it is shown at. A source mermaid-svg rejects is shown as code with the error.
- **Selection and the text menu.** `ui/selection.rs` is egui's `LabelSelectionState` adapted (an egui plugin, `TextSelection`): only the primary button starts or ends a selection, so a right click keeps it for the context menu, and so does a press on another layer (the menu); `label` returns the label's selected characters, which `draw_rich_rows` and `draw_code` turn into `Selected` (bytes of `Rich::text` through `RichJob::char_bytes`) in `RenderCtx::selected`, kept in `ViewState::selected` after the frame. `text_menu` opens only with a selection or on highlighted text (`MenuPoint`, the place under the right click): Copy (`selection::copy`, at the end of the pass), Copy as Markdown, Highlight, Remove highlight. The last three are `ViewAction`s; `App` sends them with the selection to the file thread (`FileJob`), Ctrl+Shift+C and Ctrl+H do the same (Ctrl+Shift+C also drops the `Event::Copy` egui-winit makes of it). Every document label (code blocks and alert titles too) must go through `selection::label`, or selections across it break.
- **Images.** On Windows, egui_extras requires `file:///C:/…` (three slashes). Two slashes are parsed as a UNC host. See `file_uri`.
- **Animation.** egui animates GIF/WebP only for URIs ending in `.gif`/`.webp`. `ui/animation.rs` covers the rest: `frame_uri` sniffs the loaded bytes (query-string URLs, extensionless GitHub `user-attachments` links, APNG) and picks `uri#frame` itself; `ApngLoader` decodes APNG; frame delays ≤ 10 ms play at 100 ms as in browsers.
- **SVG.** egui_extras' `svg` feature is off: its loader takes only `.svg` URIs and draws no text. `ui/svg.rs` replaces it, sniffing SVG by bytes or media type (shields.io badges have no extension) and rendering text with resvg's `text` feature. Fonts (Verdana, Arial, Segoe UI…) are read on the first SVG that has `<text>`, never at startup. `rasterize` keeps an SVG within the GPU's `max_texture_side` and 64 M texels, whatever size it names.
- **Texture limit.** egui_glow asserts that a texture fits `max_texture_side`, so with `panic = "abort"` an oversized image ended the app. `ui/limit.rs` (`LimitLoader`, installed after every other image loader) asks the loaders before it itself and halves a too-large image by averaging texels; its `source_size` stays, so it is drawn at its own size.

### Other modules

- `style.rs`: palettes, egui visuals, and font loading. The light theme is GitHub's; the dark one is either metalmpv's neutral greys (`DarkStyle::Grey`, the default) or GitHub's nearly black one (`DarkStyle::Black`), chosen in the context menu of the theme button (`ui::dark_style_menu`), which calls `apply_visuals` again. Fonts: `load_fonts(body, mono)` reads the reader's fonts (`Settings::font`, `mono_font`) or the platform's (Segoe UI with real bold and italic faces, plus Consolas, on Windows) with egui's bundled fonts as fallbacks; a missing bold italic face falls back to bold (slanted) or italic. The body size is `style::body_size()`, an atomic set from `Settings::text_size`, not a constant; everything in a document scales with it, the interface keeps its sizes.
- `fonts.rs` and `ui/text.rs`: the Text panel (Aa button). Its last row sets the highlight colour of the current theme (`Settings::mark_color` / `mark_color_dark`, `#rrggbb`; `style::mark_presets` or egui's colour button), which `window_ui` puts into the frame's `Palette::mark_bg`. `fonts::system_families` lists the installed families with fontdb, on a background thread when the panel first opens, never at startup. A chosen family is resolved off the UI thread to a `FontSpec` (files, `.ttc` index, and for a variable font axis values such as `wght` 700 or `ital`/`slnt` for the missing styles, applied through `FontTweak::coords`) and saved, so startup reads those files at the same cost as the defaults. `fonts::read` checks a file with skrifa, egui's parser, because egui panics on a font it cannot parse. After `set_fonts` the next frame measures the ascents and bumps `fonts_generation` (`App::remeasure_fonts`). List markers are placed from the baseline (one ascent below the row's top), so they follow other fonts.
- `app.rs`: windows and tabs. `App::windows` holds the root (`ViewportId::ROOT`) first, then detached windows, each an immediate egui viewport (`show_viewport_immediate`) drawn by `window_ui` with `App::current` set to it; everything per window (tabs, find, confirm, title, hwnd) lives in `Window`. A tab is dragged by its title (`TabDrag`): along the bar it is reordered, dropped on another window's `outer` rect it moves there, dropped outside every window it gets a new viewport placed so the tab lies under the pointer (`detach_tab`; the tab's context menu does both without the mouse). Child viewports die with the root, so closing the root while detached windows exist closes its tabs and moves it to the place of the last focused child (`adopt_window`). eframe gives no handle for a child window, and Windows would show it white before its first frame, so it is made hidden (`with_visible(false)`) under a title of its own, `hidden_title` (two windows may show the same document, under the same title), and `App::appear` (`Window::appear`, `Appear`) finds it by that title among the thread's windows, hidden ones too (`caption::thread_window`), cloaks it, gives it the dark caption and its real title, shows it (`ViewportCommand::Visible`) and uncloaks it after 3 painted frames; not found within `LOOK_FRAMES` (10), it is shown as it is. Zoom is per egui context, so every window zooms together. Link resolution (`#anchor`, relative `.md` opened in a tab with fragment, `file:` URLs as paths, other targets via `open` on a background thread; `ui/confirm.rs` asks first for runnable files, other schemes than http(s)/mailto, and UNC paths on another host than the document's), shortcuts, find bar, and the TOC panel (left or right, `Settings::toc_side`, chosen in the context menu of its button or of the panel, `ui::toc_side_menu`); at most 35% of the window wide and hidden below 560 points.
- Toolbar icons (`ui/mod.rs`) are painted in 1.3-point lines on a 14-point grid; `rounded` bridges corners with curves and `round_line` adds round ends, since egui joins with sharp mitres and ends lines flat.
- `src/icon.rs` draws the app icon procedurally and has no dependencies. `build.rs` includes it via `#[path]`, writes the `.ico` embedded by `winresource`, and writes `app_icon_{64,128,256}.rgba` into `OUT_DIR`. `main::embedded_icon` includes those bytes for the window icon, the start page and About (`ui::app_icon`), so nothing is rasterized at startup. This is the same scheme as the sibling apps qview and disk_flashlight, whose About dialog, start screen and theme button (`ui::theme_button`) these UI pieces mirror.
- `vault.rs`: Obsidian vaults (the nearest folder up holding `.obsidian`, `root_of`). Obsidian finds a linked note or attachment anywhere in the vault, so a relative link or image that is not where it says is looked up by the end of its path among the vault's files (`Index::find`: the candidate whose folder shares most with the document's, then the shortest; `.md` added for a target that is no note; dot folders and `node_modules` left out). Nothing runs at startup: `viewer::image_source` asks only when egui failed to read the file (`try_load_bytes`), through `vault::locate`, which lists the vault on a thread of its own and says `Waiting` meanwhile (the block stays unmeasured, `RenderCtx::pending`); a link click and printing use `locate_now`, which lists at once and lists again a listing older than 10 s that misses. What was found is remembered until F5 (`vault::forget`). `link_missing` tells `rich_job` whether a link's file is neither next to the document nor in the vault, so it is drawn fainter as in Obsidian: the first ask queues the path for a thread of its own (`links`) and says no, the answer is remembered per folder and path and repaints.
- `edit.rs`: the writes to a document, ticking a task list item and highlighting (`Change`). `ListItem::task` carries comrak's position of the mark between the brackets and the mark itself (`Task::mark`: comrak's `relaxed_tasklist_matching` takes any, as Obsidian does; only ` `, `x` and `X` can be clicked, the viewer draws `/` half filled, `-` with a dash and others in the box); preprocessing keeps line numbers and never touches what precedes the box on its line but a comment taken out (`%%c%% - [ ]`), whose column `preprocess::CommentColumns` maps back, so that position holds in the file. A click (`ViewAction::ToggleTask`), a highlight or a removal goes to one file thread (`App::send_file_job`), so changes are written in order; `edit::apply` reads the file again, checks the change fits it (the tick: `[`, ` `/`x`/`X`, `]` where the parse put them; a highlight: `markdown::source`), and writes the file back in the encoding it was read in (refusing a lossy decode or an encoding that would not round-trip). `AppMsg::Written` reloads the tab at once, or puts "not saved" in the status line with the reason on hover (`Tab::failed`). Each change is pushed on `Tab::undo` with the change that undoes it (the opposite tick, or `Change::Restore` of the text before a highlight) and the digest of the bytes written; Ctrl+Z writes it only if the file still has that digest, since an edit elsewhere may have moved the lines. "Copy as Markdown" goes through the same thread (`FileJob::Markdown`, the file read again) and comes back as `AppMsg::Markdown`.
- `update.rs` and `win.rs`: the update check of the family (qview's module): opt-in in About (`Settings::check_updates`, `last_update_check`), at most once a day from frame 2, or "Check now". `win::https_get` asks `api.github.com/repos/Fan4Metal/metalmd/releases/latest` through WinHTTP (system TLS and proxy, no HTTP crate); a newer tag shows `ui::update_button` left of About, which opens the release page built from `CARGO_PKG_REPOSITORY`. `cargo test update -- --ignored` asks GitHub for real.
- `print/`: printing and PDF (`Ctrl+P`, `Ctrl+Shift+S`, the printer button's menu, `ui::print_button`). `print::html::page` writes the `Document` (not comrak's HTML, so raw HTML stays reduced and nothing from the file reaches the page unescaped) as a web page with a GitHub-like print style sheet: formulas as SVG from `ui::math::html_svg` (sized in ems, on the baseline), diagrams as SVG from `ui::diagram::html_svg` (usvg's reading with text as outlines, the drawn area, ids prefixed per diagram), code coloured by `highlight::highlight_now` in the light theme, `<details>` as the reader left them (`ViewState::toggled_details`), links into the document as `#b<top-level block>` ids, relative links and images as `file:` URLs. `print::spawn` writes it to `%TEMP%\MetalMD` and hands it to `print/webview.rs` on a thread of its own: WebView2 (webview2-com; the loader is linked statically, no DLL) in a window of that thread, hidden for `PrintToPdf` (A4, Letter where `LOCALE_IMEASURE` says inches), shown over the app's window for `ShowPrintUI` with the browser's dialog; a script added to the page posts `afterprint`, which closes the window, as does Esc. Nothing of it runs before the reader asks, so startup is unchanged (checked with `--bench`). Without the WebView2 runtime the page opens in the default browser with a script that calls `print()`. `AppMsg::Printed` puts the outcome in the status line (`PrintStatus`; a saved PDF opens with a click). `cargo test pdf_of_the_sample -- --ignored` writes a real PDF.
- Session and navigation (`app.rs`): started without files and not benchmarking, `main` opens `Settings::session` (the tabs of the last run, in window order) with `session_active` in front; only that tab is loaded before the window, the rest are `Startup::deferred` and load in `start_background_services`. A restored tab whose file is gone closes (`Tab::restored`). `remember_session` writes the tabs and each one's `ViewState::saved_position` (a pending jump, else the reading position) before every save; `drop_tab`, the one way out for a tab, keeps the closed tab's position and pushes it on `closed_tabs` for Ctrl+Shift+T. `Settings::positions` (the last 100 documents read) is applied when a document is first loaded into a tab without an anchor. Jumps go through `Tab::jump_from_here` (back stack, forward cleared); Alt+Left/Right and the mouse buttons call `Tab::step`.
- `editor.rs`: Ctrl+E and the tab menu start `Settings::editor`, chosen in the tab's Editor submenu (`app::editor_menu`: `editor::installed()`, listed once per run on first use: the known editors' install paths, then `SHAssocEnumHandlers` for `.md`/`.markdown`/`.txt` with `ASSOC_FILTER_RECOMMENDED`, exes only, Store apps, browsers and MetalMD left out, Notepad last; Other Program… picks an exe), else the first found, at `Document::lines[first visible block]` (each top-level block's line in the file, recorded by `Document::build`; preprocessing keeps lines), passing the line as each editor wants it (`-g file:line`, `-nLINE`, `file:line`).
- `ui/lightbox.rs`: the picture viewer, after the reader's Image Viewer plugin for Obsidian (`D:\Projects\obsidian_image_viewer`; its defaults: step 1.15, zoom from 0.2 to 12 times the start zoom, backdrop 0.92, thumbnails 84×64, looping). A click on an image that is not a link, or on a diagram, is `ViewAction::ShowPicture`; `App::handle_action` gives the `Lightbox` every picture of the document (`viewer::document_pictures`, in document order, by the URI or source the click gives; `picture_name`) and the clicked one's place. It draws in an `Area` of `Order::Middle`, over the document and its windows but under the menus (`Foreground`), its own context menu among them: the top row ("3 / 12", the name), the stage (the picture clipped to it; it pans only when larger), the ‹ › buttons and the thumbnail strip (a horizontal `ScrollArea`, cropped thumbnails, the current one scrolled into view). It takes ←/→, `+`/`-`/`0`, the wheel (zoom about the pointer, or with `WheelMode::Navigate` one picture per notch and Ctrl+wheel zooms), drags and double clicks; `handle_shortcuts` returns early while it is open, closing it on Esc. Its context menu edits `Settings::viewer` (`ViewerSettings`: thumbnails, their `ThumbShape` and `thumb_height`, 40 to 160 points, clamped where it is read, arrows, wheel, `StartZoom`), which the app saves; a click that closes that menu does not close the viewer. A diagram is drawn again at the zoom through `DiagramRenderer::get_zoomed`, a render-cache variant of its own (bit `ZOOMED`), so the document behind keeps its texture.
- Find options: `FindOptions` (`Settings::find_case`, `find_words`, toggles in the find bar and Alt+C / Alt+W, whose typed letter is dropped) go into `find_with`; `viewer::paint_find_marks` marks each block with a match along the right edge of the view. The text column's width is `style::content_width()`, an atomic like the body size, from `Settings::text_width` (the Text panel; the end of `CONTENT_WIDTHS` is the whole window). F11 toggles full screen, which `remember_window` does not save.
- Context menus: every one is `ui::menu::context_menu(&response, …)`, not `response.context_menu` (as in qview): `ui::menu::RightClick`, from `App::raw_input_hook`, holds the right button's press back and passes it on with the release, at the release's position, since egui counts a click only within 6 points and 0.8 s; a press anywhere off the menus (`Order::Foreground`) closes it, also one followed by a drag; a right click on the widget while its menu is shown opens it anew at the pointer.
- `placement.rs`: in `App::new`, while the window is hidden, moves it into the nearest monitor's work area if its caption cannot be reached (the saved monitor is gone), then maximizes it if it was closed maximized (`show_maximized`). The saved geometry is in unzoomed points (`remember_window` multiplies by the zoom), because the window is created before `set_zoom_factor`.
- `watcher.rs` watches the parent directory, not the file, so save-by-rename is caught, and coalesces events for 150 ms. A folder is watched anew for each document opened from it and on F5/Retry (`FileWatcher::refresh`): a watch on a folder deleted and made again sees nothing, and notify does not say so.

## Conventions

- Every user-visible string goes through `tr!("English", "Русский")` (`src/i18n.rs`, the scheme of qview). The language follows the Windows UI language (`i18n::system_lang`) unless chosen in About (`Settings::language`, `system`/`en`/`ru`); `main` sets it from the settings before the window is created, About applies a new choice at once. Strings are built every frame, so nothing caches translated text. Log messages, alert titles (`[!NOTE]` and others, as on GitHub) and file dialog type names stay English.
- `src/markdown/preprocess.rs` and `src/fs_text.rs` contain BSD-3 code from Markpad. Keep their copyright headers, and update `THIRD_PARTY_LICENSES.md` if more Markpad code is ported. That file holds the notices of the code ported from Markpad and egui only; the notices of the crates compiled in (procedural macros and what only they use, syn, quote and the like, run in the compiler and are left out), of egui's and RaTeX's embedded fonts and of the WebView2 loader are `licenses/THIRD_PARTY_NOTICES.txt`, and those of the syntax definitions and colour themes `licenses/SYNTAXES_AND_THEMES.txt`, both written by `python tools/notices.py` (the second through the ignored test `ui::licenses::tests::write_syntaxes_and_themes`, since two-face's listing is a binary dump only Rust reads). `ui::licenses::tests` checks the first against Cargo.lock's FNV-1a hash and the second against two-face's listing. `ui/licenses.rs` shows all four texts from About's **Licenses…** (metalamp's window: a list on the left, the text wrapped at words for `show_rows`), and the installer and the portable zip ship the files.
- Before claiming a performance change, check it with `--bench`. Run it several times and ignore the first, cold run.
